# Admin Product Variant Builder

Add a variant builder to the admin add/edit product modal: define option groups (e.g. Color, Size), auto-generate all combinations, and set per-variant **price, stock, and image**. Stored in the existing `products.attributes` JSONB (no DB migration, no backend changes). Format is compatible with the existing CJ-import variant rendering used by the storefront and cart.

## Data format (in `attributes`)
```json
{
  "variant_groups": ["Color", "Size"],
  "variants": [
    {
      "variant_name": "Red / S",
      "options": { "Color": "Red", "Size": "S" },
      "stock": 5,
      "retail_price_usd": 12.00,
      "image_url": "https://..."
    }
  ]
}
```
`variant_name` / `stock` / `retail_price_usd` / `image_url` match the existing CJ format, so all current storefront/cart rendering keeps working. `options` + `variant_groups` are new keys that enable grouped rendering.

## 1. Admin panel — `frontend/admin/index.html`
- New **"Variants"** section at the top of the modal's right column (before Attributes):
  - Dynamic option-group rows: group name (e.g. "Color") + comma-separated values (tag-style chips).
  - "Generate combinations" auto-builds a variant table; combos persist their price/stock/image when groups change (regeneration preserves matching rows).
  - Variant table: combination label, **price** (pre-filled from product price), **stock**, **image** (thumbnail picker fed by the existing image-manager slots, plus custom URL), remove button.
  - Total stock readout that syncs the product's main `Stock` field (sum of variant stock).
- JS state + helpers: `variantGroups`, `variantRows`; `addVariantGroup()`, `regenerateVariantRows()`, `renderVariantBuilder()`, `collectVariants()` (produces the JSON above), `populateVariants(product)` for edit mode (rebuilds groups from `options`, falling back to splitting `variant_name`).
- Submit handler: merge variants into `attributes`; when variants exist, set product `stock` = sum of variant stocks.
- Small CSS for the builder (matches existing modal styles).

## 2. Storefront — `frontend/product-detail.html`
- In `renderAttributes()`: if `attrs.variants` entries carry `options`, render **one selector per group** (a "Color" group renders as color swatches, others as chips) instead of one flat chip list; hide the duplicate `colors`/`sizes` attribute selectors whose values are covered by variant groups.
- Selecting a group value filters remaining chips: combinations with no matching in-stock variant are disabled / marked out of stock.
- When a full combination is chosen: swap the displayed price and main image from that variant (reuses existing `selectVariant` / `data-price` / `data-image` mechanisms).
- Add-to-cart validation already requires every `.variant-selector` fieldset to be chosen — grouped selectors reuse it. CJ-imported products without `options` keep the existing flat chip behavior.

## 3. Cart — `frontend/cart.html`
- Variant drawer: on confirm, when the chosen combo has an `options` map, write the full options map into `selected_options` (instead of `{variant: "Red / S"}`), so grouped products stay consistent; price uses the variant's `retail_price_usd`. Flat CJ variants behave exactly as today.

## 4. Backend
- **No changes.** `ProductCreate.attributes` is a free-form dict already persisted as JSONB; cart already supports `unit_price` override and dedupes on `selected_options`.
